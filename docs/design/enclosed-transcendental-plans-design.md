# Enclosed transcendental plans · `spec:nrz:enclosed-transcendental-plans-design`

This design specifies prepared binary64 elementary kernels for tiled and streamed numerical evaluation against (`spec:nrz:tiles-streams-design`). It supplies operation laws and proof obligations, not an implementation claim or an LC model. Exact authority, lowered computations and current applications retain their separate identities under (`rule:nrz:tiles-streams-identities`). The kernel contracts below are the interface for joint review with consumers; a consumer needing another law or domain must identify that requirement rather than infer it from a similar function name.

## Scope and ownership · `sec:nrz:transcendental-scope`

**Decision (Prepared operation families)** · `dec:nrz:transcendental-families`

Prepare exp, expm1, sigma, tanh and positive-base dyadic powers. Their coefficients and finite error arguments are checked once for an admitted box, target and arithmetic schedule. Subsequent numerical applications compute fresh answers at the supplied points or boxes inside that domain; a prepared domain enclosure is not a cached point answer. CAS retains exact mathematical authority, bindings retains original-operation correspondence and complete reading/companion inventories, scalar owns enclosure primitives, and matrix owns numerical region kernels and application evidence under (`req:nrz:tiles-streams-plan-owner`), (`def:nrz:descriptor-binding-lowering`). No crate dependency is reversed and no consumer activation becomes an engine type.

## Kernel contract · `sec:nrz:transcendental-kernel-contract`

**Definition (Endpoint guarantees)** · `def:nrz:transcendental-endpoints`

Let an admitted input be the exact point a or the ordered exact real box [a,b], represented by checked input and import-error bindings. Each law below is increasing on its domain. A successful result [L,U] encloses its entire image: L <= f(a) <= f(b) <= U. For an absolute target p, the lower endpoint error f(a)-L and upper endpoint error U-f(b) are each at most 2^(-p). For a relative target they are respectively at most 2^(-p)\*abs(f(a)) and 2^(-p)\*abs(f(b)). An endpoint whose function value is exactly zero is published exactly for the relative contract. The intrinsic width f(b)-f(a) is not numerical error and cannot be required to fit a point target. Endpoint certification may use the stronger sufficient test that its enclosing interval has width at most the absolute target, or at most the relative target times a certified lower magnitude. This does not redefine the agreed endpoint criterion. A point has the same lower and upper endpoint obligations; any additional total-width request is a separate consumer check.

**Table (Laws and guarantees)** · `tab:nrz:transcendental-laws`

|Operation|Exact law|Admitted complete input domain|Enclosure and target|Operation-specific evidence in addition to the common result evidence|
|---------|---------|------------------------------|--------------------|---------------------------------------------------------------------|
|exp|f(x)=exp(x)|\[\-2,0\]|Increasing image enclosure; absolute endpoint target; exp(0)=1 exactly is available.|Exponential reduction identity, constant bounds, polynomial remainder and reconstruction rounding for the selected schedule.|
|expm1|f(x)=exp(x)-1|\[\-2,0\]|Increasing image enclosure; relative endpoint target; f(0)=0 exactly.|Cancellation-free small-argument schedule or a proved away-from-zero subtraction bound, with its switch coverage and relative-error conversion.|
|sigma|f(x)=1/(1+exp(-x))|\[0,2\]|Increasing image enclosure; absolute endpoint target.|Negation correspondence, exp enclosure, positive denominator and outward reciprocal/composition; f(0)=1/2.|
|tanh|f(x)=-expm1(-2x)/(2+expm1(-2x))|\[0,1\]|Increasing image enclosure; relative endpoint target; f(0)=0 exactly.|Exact argument scaling, expm1 correspondence, strictly positive denominator, quotient error and relative-error conversion.|
|power|f(x)=x^(m/2^k), with reduced exact exponent q=m/2^k|0\<a\<=b\<=2 and 0\<q\<=1, q dyadic|Outward enclosure only; no requested width target.|Exact exponent classification, repeated-root/integer-power identity, positive root bounds and all rounding; x=1 gives 1 exactly.|

**Rule (Closed numerical refusals)** · `rule:nrz:transcendental-refusals`

Each operation refuses an operand outside its complete domain with outside-domain; power also uses outside-domain for an exponent outside (0,1]. Power refuses an in-range non-dyadic exponent with non-dyadic-exponent. Every operation refuses any supplied operand endpoint whose magnitude is nonzero and below 2^(-1022), the smallest positive normal binary64 value, with below-normal-operand. This is a magnitude rule, including negative endpoints, not the signed comparison x < 2^(-1022). Exactly zero remains admitted wherever the operation's domain admits zero; a power base with zero lower endpoint remains outside-domain. The below-normal rule governs operand endpoints, not all real interior points of a box and not every intermediate term or output. Targets or finite schedules whose required enclosure cannot be certified in the declared binary64 environment refuse with target-not-certifiable. These four names are the closed numerical refusal vocabulary. Resource exhaustion, stale attachment, malformed representation and unsupported engine evidence remain the engine's distinct failures, not mathematical domain refutations. Multiple invalid premises retain their checks and diagnostic scope; acceptance fixtures isolate one cause and do not impose a new precedence rule.

**Rule (Evidence of a result)** · `rule:nrz:transcendental-result-evidence`

Each successful masked application retains the authenticated prepared law and lowering revision, original operation and exponent where present, admitted domain and target, arithmetic schedule/environment, constant/coefficient import error, and current ordered input/output bindings, region versions, maps and masks. It publishes finite centers with total bounds and numerical-only error companions under (`thm:nrz:descriptor-binding-kernel-enclosure`); conversion from endpoint bounds to center/radius is itself outward and included in the target check. The record distinguishes whole-input coverage from evaluation at the nominal center, and numerical error already covered by the total bound is not added twice. Domain, target and refusal masks identify which cells have results. Evidence is shared authority plus current numerical companions and attachment, not a new exact certificate or descriptor per cell. Publication and semantic use retain (`rule:nrz:tiles-streams-barrier-publication`), (`rule:nrz:descriptor-binding-certified-feedback`). A numerical refusal carries its original cell association, reason and unavailable output, never an uncertified substitute value.

**Example (A binary64 target that cannot be met)** · `ex:nrz:transcendental-spacing`

For exp(-1), the exact value lies strictly between 1/4 and 1/2 and is irrational. Adjacent binary64 values in that binade are separated by 2^(-54). Any enclosing binary64 endpoints therefore have width at least 2^(-54). Even allowing two endpoint errors of 2^(-60), their sum is at most 2^(-59), smaller than that spacing. Thus the 60-bit absolute request refuses. An exact rational evaluator on a finer grid can succeed at the same request and cannot establish binary64 impossibility. This argument assumes the published endpoint representation is binary64; a center/radius export must satisfy the same effective endpoint contract, not hide extra precision in an unadvertised representation.

## Preparation and numerical schedules · `sec:nrz:transcendental-preparation`

**Rule (Authority and application keys)** · `rule:nrz:transcendental-keys`

Instantiate (`def:nrz:tiles-streams-exact-key`) with the canonical original law, exact admitted box, target kind and bits where applicable, exact exponent, all analytic premises, constant identities, finite schedule and proof/checker revisions. Distinguish a statement key from a proof-byte key when witness identity matters. Apply (`def:nrz:tiles-streams-lowering-key`) to its checked binding maps, format, masks, schedule, coefficient specialization and error policy, including whether an FMA instruction or separate multiply/add steps are proved. Actual floating data, addresses, arrival order, tile ordinal, occupancy and live versions do not become exact authority keys under (`rule:nrz:tiles-streams-key-boundary`). Current attachment checks still authenticate them where required. Specializing to exact rational endpoints intentionally creates another mathematical domain key; reusing a general domain does not do so for every incoming point.

Lookup precedes construction under (`rule:nrz:tiles-streams-lookup-order`). A hit charges actual key, lookup, authentication, application and any fresh import/copy work under (`rule:nrz:tiles-streams-cache-charge`); it does not reconstruct constants or replay their proofs. A miss prepares and checks finite exact evidence with the cumulative caller ledger before admission. Constants use (`def:nrz:tiles-streams-constant-key`), while imported numerical coefficient regions use (`def:nrz:tiles-streams-prelude-key`). Full flush releases numerical preludes; warmed exact authority can survive and serves a charged fresh import. No cache key or allocation choice waives an operand or target check.

**Requirement (A finite schedule has a finite proof)** · `req:nrz:transcendental-schedule-proof`

Preparation establishes exact rational bounds for constants, coefficient approximation, truncation, reduction and every rounding stage, and checks their composed bound over the admitted domain. It fixes finite degree, reduction candidates, switch thresholds, root steps and exponent schedule before numerical execution. Bounded directed interval operations or error-free transforms with a proved outward residual may implement the bound; an ordinary library transcendental followed by one nextafter has no such proof. The arithmetic model identifies rounding mode, subnormal behavior, compiler contraction and permitted target instructions. Gradual underflow must be accounted for with absolute error where a relative unit-roundoff model fails; flushing subnormals to zero is not silently admitted. Exact preparation/replay follows (`rule:nrz:enclosures-design-checker`), (`rule:nrz:enclosures-design-work`); native execution does not replay that checker per cell.

**Requirement (Exponential schedule evidence)** · `req:nrz:transcendental-exp-schedule`

A range-reduced candidate uses x=k\*ln(2)+r and exp(x)=2^k\*exp(r). On [-2,0], exact floor reduction needs k in {-3,-2,-1,0} and 0<=r<ln(2). A finite ln(2) enclosure makes classification ambiguous near k\*ln(2); the schedule must cover every feasible candidate, account for the resulting residual interval and hull the valid images, or use another proved schedule. It must not round a cut and assume its side. For a residual bound abs(r)<=rho<=1 and degree N>=1, the Taylor tail is at most rho^(N+1)/(N+1)! divided by (1-rho/(N+2)), since successive absolute omitted terms have ratio at most rho/(N+2). This finite rational majorant, coefficient errors, uncertain reduction and reconstruction errors all enter the endpoint budget. Preparation proves the residual range for the actual classifier, including boundary ambiguity; the exact-floor range alone is insufficient. N and the ln(2) precision are chosen to fit the target after rounding, or preparation refuses.

**Requirement (Cancellation-sensitive schedules)** · `req:nrz:transcendental-small-schedule`

For x=-a with 0<a<=1/2, evaluate expm1(x) as x times a polynomial starting with 1, rather than subtracting two rounded numbers near 1. The alternating series through degree N has absolute remainder at most a^(N+1)/(N+1)!, and 1-exp(-a)>=a-a^2/2>=a/2, so its truncation relative error is at most 2\*a^N/(N+1)!. All arithmetic and coefficient errors still need outward propagation. An away-from-zero branch with a>=s>0 can convert an absolute exponential/subtraction bound using 1-exp(-a)>=s/(1+s), from exp(s)>=1+s. Any selected switch s, equality ownership and overlap schedule require both proofs; no particular s or degree is established by these inequalities alone. Exactly zero bypasses cancellation after validating the original input. Tanh uses the expm1 form in the kernel table: for e=expm1(-2x), 2+e=1+exp(-2x)>1. The map -e/(2+e) has derivative -2/(2+e)^2, and relative sensitivity magnitude 2/(2+e)<2 for x>0. These bounds guide, but do not replace, the finite quotient-rounding and final target checks. Sigma similarly uses a positive denominator and outward reciprocal; its argument sensitivity sigma'(x)=sigma(x)\*(1-sigma(x))<=1/4 includes argument import error.

**Requirement (Power schedule evidence)** · `req:nrz:transcendental-power-schedule`

Classify the exact reduced exponent before conversion to floating point. For q=m/2^k, compute k positive square roots followed by a fixed integer-power schedule for m; preparation bounds the supported integer size, step count and outward rounding without silently capping the mathematical domain. Unsupported resource sizes report their resource limit. The law is increasing in the positive base. Squared endpoint inequalities can check a proposed square-root enclosure, with a proved outward correction for binary64 rounding. Products include all input and roundoff errors. No log/exp approximation is needed for this route. The normal-operand guard applies to the original base endpoints, not to a fictitious new client request at every internal step. A scalar square-root primitive's own stronger guard must nevertheless be discharged before calling it. Width is not promised for power; useful sharpness is measured separately. Negative exponents, exponent zero and exponents above one are not admitted by this plan even if a general rational reference evaluator supports them.

## Execution over regions · `sec:nrz:transcendental-regions`

**Rule (Masked numerical applications)** · `rule:nrz:transcendental-region-application`

The same lowered plan applies over finite tiles and arrived stream-segment regions under (`rule:nrz:tiles-streams-lowering-application`). It consumes only demanded, present input entries and their matching companions, with no read through a hole; empty masks perform no scalar evaluation. Each cell computes a fresh endpoint enclosure using the prepared finite schedule, then contributes success or typed refusal to the corresponding output mask. Guard classification, rounding and mask arithmetic are native work. There is zero exact Work, descriptor construction or CAS invocation per cell between barriers, including hidden child budgets. Predeclared scratch, coefficients and output companions retain total binding coverage and engine lifetime protection. Target checking is conservative: inability to establish the bound yields a refusal, not a guessed last bit. Repeated coordinates retain their dependence under (`rule:nrz:descriptor-binding-error-composition`).

**Rule (Refused cells and decisions)** · `rule:nrz:transcendental-barrier-route`

Native guard/refusal masks are numerical evidence attached to the current input versions; they do not themselves select a semantic branch. A consumer decision barrier consumes them through its declared membership recipe under (`def:nrz:tiles-streams-membership-recipe`). It may publish the refusal, select an already declared fallback/refinement, or remain undecided when the premise is not established. Exact rational fallback is charged at that barrier and publishes its own representation and assurance, rather than being counted as a successful binary64 kernel. It cannot satisfy an impossible binary64 output request by renaming rational endpoints. Remaining allowances and spent Work persist across attempts under (`rule:nrz:tiles-streams-undecided`). Uniform branches may share checked authority; a nonuniform input does not require one exact descriptor per cell. A finite tile's refusal does not erase other cells' valid answers.

Flush follows (`def:nrz:tiles-streams-node-flush`), (`rule:nrz:tiles-streams-flush-completion`). The pointwise kernel uses its actual available mask; missing required inputs remain unavailable when upstream is terminal. A consumer barrier states its own flushed readiness and aggregate meaning. This plan adds neither a stream finality protocol nor an LC decision policy. Output readers and evidence delivery retain their pins until finished; warm authority does not keep numerical heap occupations alive.

## Consumer targets · `sec:nrz:transcendental-targets`

**Rule (End-to-end width belongs to the consumer)** · `rule:nrz:transcendental-target-budget`

A consumer starts with an exact expression, input uncertainty and a final error requirement. It allocates allowances to input/constant imports, each operation and restoration using full-box interval propagation or proved sensitivity bounds, then checks the final enclosure. A plan receives only its operation's domain and endpoint target. Two extra bits in an inner call are not a universal composition theorem. Where uncertainty alone exceeds a total-width requirement, raising arithmetic precision cannot solve it. At a zero of a relative-target operation exact zero handles the endpoint; near a square-root singularity use enclosure propagation or a positive lower bound, not an unbounded derivative treated as a constant. Refinement is finite, explicit and charged at its appropriate phase.

**Example (A three-square-root consumer)** · `ex:nrz:transcendental-activation-consumer`

One consumer uses p=s/(1+s), beta=2\*ln(2), t=tanh(p), Q(p)=sigma(beta\*p)\*sqrt(t\*(1-eta^2\*t)), and A(p)=sqrt(sqrt(Q(p)/Q(1))), with s>=0 and 0<=eta^2<1. A clamped consumer substitutes max(s,wall) before reduction. This is a consumer expression, not an engine type or a claim about a paper beyond those stated premises. Since 0<=p<1, beta<2 and 0<=t<1, the sigmoid and tanh inputs fit their domains and the radicand is nonnegative. The consumer proves Q(1)>0 and each root/normalization domain for its actual boxes; interval relaxation may still require refinement. At p=0, t=Q=A=0 exactly. This path uses zero-capable square roots, not the strictly-positive power plan at zero.

For p>0, A=(sigma(beta\*p)/Q(1))^(1/4)\*(t\*(1-eta^2\*t))^(1/8). Thus log-sensitivity to sigma is 1/4, to Q(1) is -1/4, and to t is (1-2\*eta^2\*t)/(8\*(1-eta^2\*t)). These identities do not license assuming Q monotone or ignoring the leakage factor. A consumer obtains finite bounds over its actual positive boxes, includes the beta and Q(1) enclosure errors, and budgets each primitive against the final absolute target, for example 2^(-40). If a box includes zero, direct outward composition remains the applicable check. No fixed primitive precision is promised to meet the final target for every standing, leakage or input box.

## Observation and acceptance · `sec:nrz:transcendental-observation`

**Requirement (Phase and construction evidence)** · `req:nrz:transcendental-observation-evidence`

Use the adopted vocabulary of (`dec:nrz:tiles-streams-tracing`), (`def:nrz:tiles-streams-spans`), with this operation family and revision in the fields: nrz.prepare for cold exact authority, nrz.lookup and nrz.proof for cache and proof work, nrz.replay for independent replay, nrz.lower for checked schedules, nrz.prelude for numerical imports, nrz.kernel for masked evaluation, nrz.barrier and nrz.refine for semantic decisions or fallback, nrz.publish for result availability, and nrz.flush and nrz.retire for draining and release. Existing loan/handback/deliver/wait spans identify transport and consumer latency. The subscriber attributes exclusive intervals under (`rule:nrz:tiles-streams-attribution`); no resettable second Work ledger or per-cell exact metering is introduced. Construction and CAS events must make a supposedly warm rebuild visible, including attempted and rolled-back work. Cache, mask, layout and memory events identify hits, evaluated/refused counts and retained/peak capacity. The accounting coverage manifest must name native operations with no Work charge, including allocation, imports, validation, rounding, mask scans and publication, under (`req:nrz:tiles-streams-accounting-coverage`). Zero Work is not zero time. Observer loss prevents a complete-counter claim.

**Criterion (Oracle and refusal acceptance)** · `crit:nrz:transcendental-oracle-acceptance`

Use a separately versioned oracle payload inside the CC0 dataset envelope, not problem-data v2. Its implementation supplies the schema and checker before dataset import. The proposed prepared-binary64 oracle dataset uses namespace org.naturrhythmuszentrum.test.oracle.prepared-binary64, version [1,0,0], owner NRZ, ordered sources, labels and structured independent-route records referenced by rows. Rows identify operation, exact rational point or box, exact power exponent, target, expected enclosure or one closed refusal reason, and point or separate endpoint oracle intervals. Every published endpoint oracle is the nonempty intersection of independently certified routes and is at most 2^(-120) wide. Acceptance requires the result to contain every oracle interval and meet its operation target; overlap alone is insufficient. Zero oracles are exactly [0,0]. Full box images need not have oracle-sized width. No schema or dataset is landed by this design.

The initial 17-row sample covers E1 exp(-1); E2 and E3 exp at -6931471805599454/10^16 and -6931471805599453/10^16, below and above -ln(2); M1, M2 and M0 expm1 at -2^(-10), -2^(-40) and zero; the sigma row on [6931471805599453/10^16,6931471805599454/10^16], containing ln(2); T1, T2, T0 and T3 tanh at 2^(-10), 2^(-40), zero and one; P1 power on [1-2^(-52),1+2^(-52)] with exponent 1/4 and P2 at base 1/2 with exponent 1/4. R1 uses base 2^(-1023), R2 exp(1), R3 exponent 1/3, and R4 the 60-bit exp(-1) request. Successful exp/sigma rows request 40 absolute bits; expm1/tanh request 40 relative bits; power requests only outward inclusion. Future coverage adds both sides of every implemented reduction and switch boundary, exact domain endpoints, signed below-normal controls, the smallest normal and its neighbors, operand boxes containing zero, all mask outcomes, mutated authority, stale versions and resource exhaustion.

The independent rational-grid evaluator in public peer-network-rs at 45051fb, packages/graph/src/numeric/activation/bounded.rs, provides a second reading of the elementary laws, domains and cancellation-sensitive forms. It permits a broader power domain and uses a sufficient stricter relative test; neither changes this contract. Its alternating expansion has no native reduction/switch schedule. Therefore it validates values and relevant series inequalities, but schedule acceptance additionally needs the outward-rounding proof for every admitted schedule and boundary fixtures above. Finite oracle tests do not prove a universal bound. The sample's exact CAS enclosure route and independent interval route likewise check values, not compiler arithmetic assumptions.

**Requirement (Performance evidence and reuse controls)** · `req:nrz:transcendental-measurements`

Report cold preparation, warm authority lookup, lowering, prelude import, kernel execution, barriers/refinement, independent replay, publication and flush separately, with complete end-to-end time as well. Compare varying-input kernels to plain binary64 evaluation of the same laws and materialized outputs on the same machine, pinned CPU, release build and recorded target/FMA environment; generate inputs outside the timed expression and consume all results. Report per-cell time, counts, masks, deterministic Work by charged phase, construction/CAS counts, peak numerical capacity and retained exact storage. Include logarithmic populations, multiple independent runs, uncertainty, load/pressure and refused-cell proportions, with full-output and answer-reading timings distinguished. Cold/warm, changed points inside the same domain, changed domain/target/exponent, segment arrival, sparse/empty masks and full flush followed by warm reimport exercise the reuse claim. Holding authority and schedule fixed must yield zero exact Work and zero exact construction/CAS calls inside the numerical kernel. Barriers retain their actual costs. Neither a speed ratio nor a polynomial fit grants soundness or establishes a universal throughput threshold.

## Questions for joint review · `sec:nrz:transcendental-review`

**Open Question (First certified schedules)** · `open:nrz:transcendental-schedule-choice`

Which finite exp reduction and expm1 switch schedules should the first implementation certify, and which arithmetic environments should it admit? The candidate bounds above establish proof obligations, not measured degree, threshold or FMA choices. Would a single unreduced cancellation-free schedule be preferable initially if its measured cost remains acceptable?

**Open Question (Endpoint export and consumer needs)** · `open:nrz:transcendental-endpoint-interface`

Does the joint consumer review need an explicit endpoint export alongside the engine's center/total-radius/numerical-error companions, and any additional total-width point requirement? The endpoint contract must survive outward conversion in either representation. Which further operation domains or laws does the independently designed LC consumer need, without silently widening this plan?

**Open Question (Proof implementation and fixtures)** · `open:nrz:transcendental-proof-integration`

Which existing closed enclosure schemas can express the schedule proofs directly, and which finite binary64 rounding schemas need an implementing extension? Which resource ceilings and supported exponent representations should be exposed? The implementation must bring their checkers, resource pins, payload schema and adversarial fixtures together; this design grants no accepting stub and chooses no new universal Work tariff.
